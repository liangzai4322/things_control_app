# 人生参谋部：MVP 边界与后续路线

最后核对：2026-08-07。

## 产品分工

- 人生参谋部：想清楚、做取舍、看项目健康。
- 行动盒子：快速收集、场景分发、执行和记录证据。
- 日省：读取事实、复盘承诺、生成第二天的行动。
- 云服务器：唯一正式运行状态。
- GitHub Pages：静态 PWA 前端，不保存服务器密钥。

## MVP 已实现

1. `#hq` 今日驾驶舱：
   - 唯一主动作。
   - 最多两个维护动作。
   - 停止做与继续保持。
   - 五项外部结果。
   - 昨日承诺闭环。
2. 项目中心：
   - 复用主线，不新增重复项目表。
   - 根据下一步、阻塞和最后推进时间计算健康状态。
3. 待决策队列：
   - 支持记录、标记紧急和完成决策。
4. 系统接入口：
   - 已接入日省、主线系统、行动盒子。
   - 交易、镜像、GAP 教练为明确预留位。
5. 日省桥接：
   - 外部结果与闭环同步到当日驾驶舱。
   - 次日主动作和维护动作关联或创建到盒子。
   - 升级处理自动进入待决策队列。

## V2：日省双向闭环（已实现）

1. 日省开始前运行`fetch_daily_review_context.py`：
   - 读取当天承诺、盒子完成记录、进度证据、项目预警与待决策事项。
   - 生成本地 Markdown 事实包供日省直接使用。
2. 日省完成后写入`reviewCompletedAt`与产物入口，参谋部可以区分“昨天生成的今日计划”和“今天真正完成的复盘”。
3. 今日驾驶舱增加日省闭环卡：
   - 今日日省是否已同步。
   - 今日完成、有进度和触达任务数。
   - 最近 7 天唯一承诺完成率与逐日状态。
   - 可直接查看服务器生成的今日事实清单。
4. Token 优先来自环境变量，未设置时读取用户目录下的私有文件，不进入仓库或构建产物。

## V3：日—周—月三级参谋部（已实现）

1. `#hq / #hq/week / #hq/month`形成今日驾驶舱、本周作战室和本月参谋会。
2. 周省开始前读取周期事实包，完成后同步经营裁决、唯一瓶颈、唯一实验、资源分配和记分牌。
3. 月省开始前读取月度事实包，完成后同步业务组合、战略决策、下月资源分配、三层目标和不做清单。
4. 新增`hq_period_reviews`与周期 API，周/月复盘按周期键幂等保存。
5. 周/月视图在没有正式复盘时仍展示由日省、盒子和项目中心派生的事实指标。

## V4：主副面板与执行桥接（已实现）

1. 无 Hash 访问默认进入`#hq`，人生参谋部成为主面板；`#home`保留为盒子执行副面板。
2. 所有路由顶部保留“参谋部 / 盒子”指挥切换器，主副面板共享数据但不复制职责。
3. 参谋部主动作和维护动作使用`#box/:boxId/:taskId/hq-primary|hq-maintenance`精确进入任务。
4. 盒子自动展开、滚动并高亮目标任务，展示“本周实验 → 所属项目 → 当前角色”的指挥链。
5. 指挥链支持返回参谋部和进入所属项目；桌面横向展示，手机纵向展示。
6. 周实验先使用本地周期缓存，再通过`offset=-1`周期接口刷新最近已完成周省；离线时保留任务和项目上下文。
7. 外部任务中枢在用户确认后幂等写入 TaskBox；普通任务由参谋部共享读取，AI 任务按`executionMode=ai`进入 AI 作战区，明确主动作和维护动作才额外更新驾驶舱。

## MVP 明确不做

- 不把全部 Markdown 搬进数据库。
- 不重做 TaskBox 的任务、主线和里程碑。
- 不用积分代替外部业务结果。
- 不自动推断“完成任务”等于“发布、报价或成交”。
- 不在 GitHub Pages 构建产物中写入 Token、服务器账号或密码。
- 不强行 iframe 嵌入所有交易工具。

## V5：主动作席位与子系统闭环（P0-P1 生产完成，P2-P4 待实施）

当前本地代码已将当天原始战略承诺与动态“当前行动席位”分离：`primaryTaskId`保留承诺，`currentActionTaskId`驱动首页席位，完成任务进入今日战果。下一最佳候选、投产比引擎和统一子系统接入契约尚未进入运行代码。

后续唯一实施方案见`docs/hq-primary-action-system-loop-v2.md`，顺序固定为：

1. P0：截至 2026-08-07，客户端代码、自动化、真实 API 冒烟、弱网/离线 UI 验收和服务端生产发布全部完成。除等待写入、任务版本合并、异步渲染防线和云端 tombstone 权威外，离线写入已进入持久化 outbox，重载后保持“待同步”，恢复连接后自动重放。API 的`primaryTaskId: null`清空修复已在线上通过清空、读回与原 brief 恢复验证。
2. P1：截至 2026-08-09，生产已分开今日原始战略承诺、当前行动和今日战果；全量测试、构建与线上 API 验收通过。
3. P2：增加资格门槛、可解释投产比排序和用户确认接棒。
4. P3：建立轻量子系统接入卡，只选择一个只读系统跑真实闭环。
5. P4：由日省、周省、月省校准候选规则，再对验证有效的系统开放受控写回。

P1 已完成生产发布。P2 已完成本地发布候选：现有任务评分/排序/冷却/确认复用，以及主线系统阻塞/缺下一步的原生候选和幂等建任务均已通过测试，正在发布。P3 再扩展其他子系统接入和跨周期反馈。

## 下一阶段：系统接入

### P1：完成日省自动化闭环（核心链路已完成）

- 已完成：日省开始前读取 `/daily-snapshot` 和 HQ 快照作为正式证据输入。
- 已完成：日省结束后幂等同步 HQ，并报告任务创建与更新数量。
- 已完成：驾驶舱展示最近 7 天承诺命中率，不做复杂绩效评分。
- 后续：把飞书日省与认知卡片 URL 稳定回写到日省闭环卡。
- 后续：用自动化任务在固定时段提醒尚未完成日省，而不是自动替用户生成复盘。

### P2：交易中心与系统注册表

- 新增可配置 `system_registry`，保存系统名称、入口、健康检查和负责人。
- 交易中心只汇总风险、异常和今日处理项，具体交易操作继续进入原工具。
- 为每个外部工具配置打开方式，不支持嵌入时使用应用卡片跳转。
- 系统异常进入待决策队列，不直接生成大量普通任务。

### P3：AI 作战区

- 已完成：任务中枢可把已确认任务标记为`self / ai / hybrid`并写入共享任务库。
- AI 任务状态：待派发、执行中、等待输入、需要验收、已完成、失败。
- AI 完成后必须回写摘要、文件路径或结果链接。
- 人生参谋部只展示需要人类输入和验收的 AI 任务。
- AI 结果可以成为日省证据，但不能自动算作外部结果。

### P4：事件流与长期分析

- 增加不可变 `events` 表，记录任务完成、进度、项目状态和决策。
- 周复盘、月复盘从事件流生成，不反复扫描全部 Markdown。
- SQLite 规模或并发达到瓶颈后再迁移 PostgreSQL。
- 增加服务器在线备份、数据导出和按日期恢复演练。

## 数据所有权

| 数据 | 主数据源 |
| --- | --- |
| 任务、进度、完成证据 | TaskBox |
| 主线、里程碑、下一步 | TaskBox / 人生参谋部共用 |
| 日省完整叙事 | Markdown + 飞书私有文档 |
| 今日驾驶舱结构化字段 | `hq_daily_briefs` |
| 待决策事项 | `hq_decisions` |
| 交易原始数据 | 交易系统 |
| 系统入口和健康状态 | 后续 `system_registry` |

## 成功标准

1. 打开参谋部 30 秒内知道今天唯一主动作。
2. 每个活跃项目都有明确下一步或明确预警。
3. 连续拖延的问题进入决策，不再原样滚动。
4. 日省生成的第二天行动自动出现在盒子前三位。
5. 盒子完成记录能成为下一次日省的事实证据。
6. 从参谋部进入任一派发任务后，能在同一屏看到周实验、项目归属、任务角色和返回路径。
